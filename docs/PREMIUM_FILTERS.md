# Premium-фильтры и обогащение вакансий (Promostaff Hunter)

> **Статус:** согласовано (2026-06-07). Код — по фазам 0 → 1 → 2 → 3.  
> Связанные документы: [SUBSCRIPTION.md](SUBSCRIPTION.md), [DEVELOPMENT.md](DEVELOPMENT.md) §6–7.

---

## 1. Зачем

Сейчас Premium даёт push, все категории и фильтр **только по станциям метро** (`subscribers.metro_zones`). Этого мало:

- подписчик из **Подмосковья** хочет видеть вакансии **в своём городе и в Москве**;
- исполнитель хочет **минимальную ставку** (₽/ч или ₽/смена);
- push не должен будить **ночью** или на **работе**, но **лента** должна оставаться доступной;
- часть категорий — **приоритет push**, остальные — только лента.

Параллельно выявлена проблема **обогащения данных при парсинге**: в объявлениях часто есть полный адрес, ставка и координаты, но бот их **не извлекает** → страдают и фильтры, и кнопка **«На карте»** (`build_maps_url` в `main.py`).

**Вывод:** фильтры Premium опираются на нормализованные поля в `vacancies`. Сначала — **обогащение при парсинге** (фаза 0), затем — настройки пользователя и матчинг (фазы 1–3).

---

## 2. Принципы

| Принцип | Решение |
|---------|---------|
| Push ≠ лента | Тихие часы, «занят N ч», приоритет категорий — **только push**. Лента по умолчанию без этих ограничений. |
| Фильтры ≠ парсер | Парсер решает «это вакансия или нет». Premium-фильтры — «показывать **этому** пользователю или нет». |
| География — OR | Достаточно совпадения с **любой** выбранной зоной (город / вся Москва / станция метро). |
| «Везде» | Пустые/geo-off настройки = все локации (как сейчас пустой `metro_zones`). |
| Неизвестная локация | По умолчанию **не скрывать** (`show_if_location_unknown: true`). |
| Неизвестная ставка | После улучшения парсера — редкий кейс; если поля пустые — **показывать** с пометкой «ставка не распознана», не резать молча. |
| Free vs Premium | Расширенные фильтры, push-режимы — **только Premium** (и Trial). Free: 1 категория, без push, без фильтров. |
| Часовой пояс | **Europe/Moscow** для тихих часов (как в `channel_policy.py`). |

## 3. Архитектура (вариант 2 — согласован)

### 3.1. Таблица настроек пользователя

```sql
CREATE TABLE subscriber_filter_prefs (
    user_id BIGINT PRIMARY KEY REFERENCES subscribers(user_id),
    prefs_json TEXT NOT NULL DEFAULT '{}',
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

- Одна строка на пользователя, схема в JSON — без миграции на каждый новый фильтр.
- **`metro_zones`** в `subscribers` — **legacy**, миграция при первом открытии «🎯 Фильтры Premium» → перенос в `prefs_json.geo.metro_stations`, затем чтение только из prefs (столбец можно оставить для обратной совместимости).

### 3.2. Обогащение `vacancies` (фаза 0)

Новые колонки (PostgreSQL + SQLite в `init_db()`):

| Колонка | Тип | Назначение |
|---------|-----|------------|
| `address_normalized` | TEXT | Строка для карт и отображения («Москва, ул. …, 15») |
| `geo_tags` | TEXT (JSON array) | `["moscow","balashiha","metro:taganskaya"]` |
| `rate_hourly` | INTEGER | ₽/ч, если распознано |
| `rate_shift` | INTEGER | ₽/смена / фикс за смену |
| `min_hours` | INTEGER | Минималка часов |
| `rate_effective_hourly` | INTEGER | `rate_shift / min_hours` или `rate_hourly` |
| `shift_date` | TEXT | ISO date или `today` / `tomorrow` / null |
| `shift_time_start` | TEXT | `HH:MM` или null |
| `location_lat` | REAL | Широта, если есть в посте |
| `location_lon` | REAL | Долгота |
| `enrichment_version` | INTEGER | Версия парсера обогащения (для backfill) |

Существующее поле `address` сохраняем; при сохранении вакансии заполняем **`address_normalized`** (предпочтительнее для карт).

### 3.3. Единый матчинг

Модуль **`services/subscriber_match.py`** (новый):

```python
def vacancy_matches_subscriber(
    vacancy: dict,
    prefs: dict,
    *,
    for_push: bool = False,
) -> tuple[bool, str | None]:
    """True + reason=None если подходит; False + код причины для логов."""
```

Вызывается из:

- push-рассылки (`main.py`, ~1904);
- ленты (`_feed_vacancies_for_category`) — если `prefs.apply_to_feed`.

Заменяет прямые вызовы `vacancy_matches_user_metro` для Premium-пользователей с prefs.

## 4. Схема `prefs_json`

```json
{
  "version": 1,
  "apply_to_feed": false,
  "geo": {
    "include_all": false,
    "cities": ["balashiha", "khimki"],
    "moscow": "all",
    "metro_stations": ["таганская", "сокол"],
    "show_if_location_unknown": true
  },
  "rates": {
    "loader": { "min_hourly": 480, "min_shift": null },
    "helper": { "min_hourly": null, "min_shift": 4000 },
    "promoter": { "min_hourly": 500, "min_shift": null }
  },
  "shift": {
    "no_night": false,
    "only_today_tomorrow": false,
    "earliest_start": null
  },
  "notify": {
    "quiet_start": "23:00",
    "quiet_end": "08:00",
    "paused_until": null,
    "category_push": {
      "loader": "priority",
      "helper": "feed_only",
      "promoter": "normal"
    },
    "digest_after_pause": true
  }
}
```

### 4.1. География

| Поле | Значения | Логика |
|------|----------|--------|
| `include_all` | bool | `true` → geo-фильтр выключен |
| `cities` | список slug из **фиксированного справочника** | Совпадение с `geo_tags` вакансии |
| `moscow` | `null` \| `"all"` \| `"metro_only"` | `all` — любая московская точка; `metro_only` — только если есть тег metro или moscow + станция из списка |
| `metro_stations` | список | Нормализованные названия (как `_normalize_metro_token`) |
| `show_if_location_unknown` | bool | Если у вакансии нет geo_tags — пропускать фильтр geo |

**Примеры:**

- Подмосковье + Москва: `cities: ["balashiha"], moscow: "all"`.
- «Мне всё равно куда»: `include_all: true`.
- Только метро (как сейчас): `moscow: "metro_only", metro_stations: [...]`.

**Справочник городов МО (согласовано):**

- **Фиксированный** список в репозитории (например `assets/mo_city_catalog.json`) — города и крупные населённые пункты, которые парсер умеет тегировать.
- **Свободный ввод** (деревня, ПГТ) — **не делаем**: бот не сможет сопоставить с `geo_tags` вакансии → ложное ощущение фильтра.
- **Радиус от города** — отложено (фаза 3+): потребует координат центра города и расстояния до точки вакансии; после стабилизации enrichment.

### 4.2. Ставка (по категориям)

Для каждой категории пользователь задаёт **один или оба** порога:

- `min_hourly` — минимум ₽/ч;
- `min_shift` — минимум ₽/смена.

**Сравнение:**

1. Если у вакансии есть `rate_hourly` ≥ порога → ok.
2. Иначе если `rate_shift` ≥ `min_shift` → ok.
3. Иначе если `rate_effective_hourly` ≥ `min_hourly` → ok.
4. Если цифр нет → **не скрывать** (показать; опционально бейдж в карточке).

Категории без настроенного порога — ставка не фильтруется.

### 4.3. Push и уведомления

| Режим | Поведение |
|-------|-----------|
| **Тихие часы** | `quiet_start`–`quiet_end` (MSK), **время задаёт пользователь**: push не отправляется, вакансия в ленте |
| **Занят** | `paused_until` (timestamp): push отложен до времени |
| **category_push.priority** | Push сразу, но **только вне** quiet/busy (priority **не пробивает** тихие часы) |
| **category_push.normal** | Push в разрешённое время |
| **category_push.feed_only** | Push не отправляется, лента — да |
| **digest_after_pause** | (фаза 2) По окончании quiet / «занят» — одно сообщение: «Пока уведомления были выключены, опубликовано **N** подходящих вакансий — смотрите в ленте» |

**Быстрые действия (UX):**

- «🔕 Занят 2 ч» → `paused_until = now + 2h`
- «🌙 До утра» → pause до `quiet_end` пользователя
- «🔔 Включить push» → сброс `paused_until`

**Дайджest (фаза 2):** при выходе из quiet или по `paused_until` бот считает вакансии, которые **прошли бы** фильтры пользователя, но **не были отправлены** push за этот период. Одно короткое сообщение + кнопка «📋 Открыть ленту». Без перечисления всех N карточек в чате.

Приоритет категории **не отменяет** quiet и **не отменяет** «занят» (v1).

### 4.4. Лента

- `apply_to_feed: false` (default) — geo/ставка/смена **не** режут ленту; только push.
- `apply_to_feed: true` — те же правила, что и для push (кроме notify).

## 6. Фаза 0 — обогащение парсера (обязательный фундамент)

> Без этого Premium-фильтры и «На карте» будут работать хуже, чем ожидает пользователь.

### 6.1. Текущее состояние

**Адрес** — `extract_address_from_text()` в `parser.py`:

- Приоритет: «адрес:/локация:» → **метро** → **улица без города** → **только город** из короткого списка.
- **Проблема:** строка «Москва, ул. Ленина, 15» без префикса «адрес:» часто **не попадает** в полный адрес (метро не найдено → улица без города → теряется город).
- **Проблема:** «Балашиха, …» может сохраниться только как город, без улицы.
- **Проблема:** ТЦ, ТРЦ, павильоны, venue — в бэклоге [DEVELOPMENT.md §7a](DEVELOPMENT.md), не реализованы.

**Карта** — `build_maps_url(address)`:

- Кнопка «На карте» только если `address` не пустой.
- Нет поддержки `ll=lat,lon` при наличии координат.

**Ставка** — `services/channel_rate.py`:

- Только **₽/ч**; ₽/смена, минималка часов, «550 р/час с 11 до 19» — частично.

**Координаты** — **не обрабатываются**:

- Ссылки `yandex.ru/maps/?ll=…`, `maps.google.com/?q=lat,lon`, `geo:lat,lon`, вложения с геопозицией в Telethon — игнорируются.

### 6.2. Целевое поведение обогащения

Модуль **`services/vacancy_enrichment.py`** (новый), вызов из `_save_parsed_vacancy_block` и при публикации заказчиком:

| Задача | Правила |
|--------|---------|
| **Полный адрес** | 1) Явный блок после «адрес/локация/место»; 2) Паттерн «Город, ул. …, дом»; 3) Метро + город; 4) ТЦ/ТРЦ/БЦ + название; 5) Fallback — текущая логика |
| **geo_tags** | Нормализация города, `moscow`, `mo`, `metro:<token>` из текста и адреса |
| **Ставка** | ₽/ч, ₽/смена, фикс + «минималка N ч», расчёт `rate_effective_hourly` |
| **Время смены** | «к 9:00», «с 11 до 19», «на завтра» → `shift_date`, `shift_time_start` |
| **Координаты** | Regex по URL; `Message.geo` / `MessageMediaGeo` в Telethon → `location_lat/lon`; URL карты: `?ll=lon,lat&z=16` |

### 6.3. Карта — приоритет URL

```text
1. lat/lon из enrichment → Yandex ll=
2. address_normalized → Yandex text=
3. address (legacy) → text=
4. нет данных → кнопка «На карте» скрыта
```

### 6.4. Backfill

- Одноразовый скрипт / admin-команда: пересчитать enrichment для открытых вакансий за **последние 3 дня** (`enrichment_version < CURRENT`).
- Не блокирует выкат фазы 1: новые вакансии обогащаются сразу.

### 6.5. Тесты

- `tests/test_vacancy_enrichment.py` — адреса, ставки, координаты, geo_tags (fixtures из реальных постов Excel/канала).
- Регрессия для `extract_address_from_text` — не ломать существующие кейсы в `test_parser_quality.py`.

### Истечение Premium (согласовано)

- **`subscriber_filter_prefs` не сбрасываем** — настройки хранятся «на память».
- Пока `plan != premium` или истёк `paid_until`: фильтры **не применяются** (поведение Free: 1 категория, без push, без geo/ставки).
- После **оплаты / продления** — те же prefs **снова активны** без повторной настройки.
- Экран «💎 Подписка» при истёкшем Premium: «Ваши фильтры сохранены — заработают после продления».
- `reset_premium_feed_settings` по-прежнему сбрасывает **категории** и legacy **`metro_zones`**; prefs живут отдельно.

## 10. Решения (согласовано 2026-06-07)

| Вопрос | Решение |
|--------|---------|
| **Priority vs quiet** | Priority **не пробивает** тихие часы и «занят». |
| **Дайджest** | Фаза **2**: после quiet / «занят» — «Пока уведомления были выключены, опубликовано **N** подходящих вакансий — смотрите в ленте» (+ кнопка в ленту). |
| **Время quiet** | Задаёт **пользователь** (`quiet_start` / `quiet_end`). |
| **Сброс prefs при окончании Premium** | **Нет** — запоминаем; при продлении фильтры включаются автоматически. |
| **Справочник городов** | **Фиксированный**; произвольные деревни — нет. **Радиус** — фаза 3+. |
| **Backfill фазы 0** | **3 дня**. |
