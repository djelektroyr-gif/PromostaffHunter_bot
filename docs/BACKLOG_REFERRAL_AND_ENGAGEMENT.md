> Конспект на доработки. **Не в проде.** Цифры наград и сроки — черновик; владелец продукта уточняет «что приемлемо» перед реализацией.

## 0. Почему не сейчас

Рефералку и публичные «приведи друга» **не включать**, пока не закрыты блокеры:

| Блокер | Зачем |
|--------|--------|
| **Качество парсера** | Новые пользователи по ссылке сразу видят шум/пропуски — реферал ухудшает репутацию |
| **Стабильность push / карточек / закрытие вакансий** | Базовый UX должен быть предсказуемым |
| **Монетизация Free = 1 категория** | Уже выкатано (`9580c66`); реферал не должен ломать эту модель |
| **Онboarding** | Друг должен быстро понять ценность после `/start` |

**Порядок:** парсер и проблемные места → анонсы обновлений (re-engagement) → рефералка V1.

## 1. Реферальная система (черновик V1)

### 1.1 Механика

- Персональная ссылка: `https://t.me/PromostaffHunter_bot?start=ref_{user_id}`  
  (опционально позже: короткий код `ref_a3f9` в БД).
- При **первом** `/start` с `ref_` — записать `subscribers.referred_by` (не перезаписывать).
- **Категорию по ref_ не предвыбирать** — в отличие от `vac_*` из канала, у реферала роль неизвестна до явного выбора пользователя (реализовано: `services/onboarding_deeplink.py` только для `vac_`).
- Статусы в таблице `referrals`: `clicked` → `registered` → `qualified` → `rewarded`.

### 1.2 Когда засчитывать invite (**qualified**)

Не по клику, а когда друг:

1. Новый user_id (раньше не было в `subscribers`);
2. Завершил анкету (ФИО + телефон);
3. Выбрал ≥1 категорию и нажал «✅ Завершить выбор».

*Опционально V2:* qualified+ = первый отклик или оплата Premium.

### 1.3 Награды (TBD — согласовать с владельцем)

| Кому | Черновик | Комментарий |
|------|----------|-------------|
| **Реферер** | +5 дней Premium за qualified-друга | Через `set_user_plan(..., extend=True)` |
| **Реферер** | Cap +25 дней Premium / календарный месяц | Анти-abuse |
| **Друг** | +3 дня к trial (7→10) только по ссылке | Не второй trial, а бонус к первому |
| **V2** | +14 дней рефереру, если друг **оплатил** первый месяц | Мотивация «живых» invite |

**Не делать:** деньги на карту, бесконечный Premium, награда за один только `/start`.

### 1.4 UX

- Пункт меню или экран: **«🎁 Пригласить друга»** — ссылка + Share (Telegram).
- Статистика: приглашено / засчитано / начислено дней.
- Push рефереру: «Друг зарегистрировался — +N дней Premium».
- Первый экран друга после `ref_`: «Вы по приглашению — бонус +3 дня к пробному Premium».

### 1.5 Анти-fraud (MVP)

- Один реферер на пользователя; нельзя ref сам на себя.
- Одна награда на пару referrer ↔ invited.
- Лимит наград рефереру в сутки (например ≤5 qualified).
- Админ: Excel / список подозрительных (много invite с одного аккаунта за час).

### 1.6 Техника (ориентир PR)

- `db.py` / `init_db()`: `referred_by`, таблица `referrals`.
- `main.py`: разбор `start=ref_` в `/start`; начисление в `finish_categories`.
- `services/referral.py` (логика qualified + grant).
- Тесты: ref self, duplicate, qualified, cap.
- Документ: [SUBSCRIPTION.md](SUBSCRIPTION.md) — строка про реферал после запуска.

## 2. Анонсы фич и выкатов (re-engagement)

### 2.1 Проблема

Уже подписанные пользователи **не видят новые функции**, пока сами не нажмут `/start` или не откроют меню. После деплоя часть аудитории «застывает» на старом опыте.

### 2.2 Цель

Периодически напоминать: **«В боте обновление — нажмите /start или кнопку ниже»**, кратко — что нового (1–3 буллета).

### 2.3 Варианты реализации

| Вариант | Плюсы | Минусы |
|---------|--------|--------|
| **A. Ручная рассылка админа** | Уже есть «📢 Рассылка» | Нужно писать текст руками; легко забыть |
| **B. Шаблон «What's new» после деплоя** | Админ выбирает версию из списка → preview → send | Нужен каталог release notes в коде или БД |
| **C. Cron «changelog ping»** | Раз в N дней тем, кто не `/start` после `APP_BUILD` | Риск спама; нужен `last_seen_build` |
| **D. `/start` показывает «Что нового»** если `seen_build < APP_BUILD` | Без spam; попадает только активных | Неактивные не узнают |

**Рекомендуемая связка для Hunter:**

1. **D обязательно:** поле `subscribers.last_seen_build` (или `app_changelog_seen`); при `/start` — блок «🆕 Обновление» если версия новее + кнопка «Понятно».
2. **B для крупных выкатов:** админ «📣 Анонс обновления» — текст из `docs/RELEASE_NOTES.md` или preset-кнопки.
3. **C опционально и редко:** не чаще 1 раза в 2–4 недели, только `is_active=1`, без Premium-спама; env `CHANGELOG_PUSH_ENABLED=0` по умолчанию.

### 2.4 Контент анонса (шаблон)

```
🆕 Обновление Promostaff Hunter

• Free: одна категория; несколько — Premium
• Бот «оживает»: статус при нажатии кнопок
• …

Нажмите /start — обновится меню.
```

### 2.5 Техника (ориентир)

- `APP_BUILD` уже в логах и `/status` — использовать как версию для сравнения.
- `init_db()`: `last_seen_build TEXT`.
- `/start`: compare + короткий changelog (файл `docs/RELEASE_NOTES.md` или dict в `config`).
- Админ: кнопка «📣 Анонс обновления» → preview → рассылка активным (reuse broadcast с rate limit).
- Не слать анонс рефералки, пока рефералка не в проде.

### 2.6 Метрики

- Доля пользователей с `last_seen_build == APP_BUILD` после выката (7 дней).
- Open rate: нажали `/start` в течение 48 ч после push-анонса.

## 5. Подписка на канал перед/после регистрации (отложено)

**Зафиксировано:** 2026-06-03 (обсуждение с владельцем).

### Зачем

Часть пользователей находит бота **по поиску**, минуя @promostaff_agency_job. Проверка подписки на канал возвращает трафик на витрину и держит единую точку входа.

### Техника (работает и для публичного канала)

- Бот — **админ** канала, в env `HUNTER_CHANNEL_ID`.
- `bot.get_chat_member(channel_id, user_id)` → `member` / `administrator` / `creator` = подписан.
- Кнопка URL `https://t.me/promostaff_agency_job` + «✅ Я подписался» → повторная проверка.
- Отдельного API «переключить пользователя на вкладку топика/канала» нет.

### UX (TBD при реализации)

| Вариант | Поведение |
|---------|-----------|
| **Мягкий** | После регистрации или в меню: «Подпишитесь на канал с лентой» |
| **Жёсткий** | Без подписки не пускать в ленту / анкету |
| **Только исполнители** | Заказчики (`employer`) без проверки |

### Не в проде

Сейчас join/leave канала только в статистике (`channel_member_events`), **гейт не реализован**.
